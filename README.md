# หมากสามเรียง 3D (XO 3D)

เกมหมากสามเรียงเรนเดอร์เป็น 3 มิติด้วย WebGL ray marching เขียนเองล้วน ๆ ไม่พึ่ง three.js
หรือ A-Frame — **ทั้งเกมอยู่ในไฟล์ `index.html` ไฟล์เดียว** เลือกขนาดกระดานได้จากเมนู
ระหว่าง **3×3 คลาสสิก** กับ **4×4 ตัดสินไว**

![หน้าตาเกม](docs/preview.png)

## กติกา

- ผู้เล่นมีหมากฝั่งละเท่ากับขนาดกระดาน (3×3 → ฝั่งละ 3 เม็ด, 4×4 → ฝั่งละ 4 เม็ด) ดำ/ขาว
  แบบหมากโก๊ะ
- **ช่วงแรก** ผลัดกันวางหมากลงช่องว่าง จนครบ
- **ช่วงที่สอง** ผลัดกัน *เดิน* หมากของตัวเองไป **ช่องว่างไหนก็ได้** ไม่ต้องเป็นช่องที่ติดกัน
- ใครเรียงหมากได้ **3 เม็ดติดกัน** ในแนวตั้ง แนวนอน หรือแนวทแยง ก่อน = ชนะ

**3×3 คลาสสิก** — เหมือนเกม Three Men's Morris ดั้งเดิม ทุกแนวยาวพอดี 3 ช่อง พิสูจน์แล้วว่า
เสมอเสมอถ้าทั้งคู่เล่นเก่ง (เหมือนโอเอกซ์ธรรมดา) มีกติกาซ่อน**ห้ามลงกลางเป็นหมากแรกของกระดาน**
กันฝ่ายเดินก่อนได้เปรียบทางสถิติเกินไป

**4×4 ตัดสินไว** — กระดานใหญ่ขึ้นทำให้มีแนวยาว 3 ช่องที่ซ้อนทับกันได้ รวม **24 เส้นชนะ**
(มากกว่า 3×3 ถึง 3 เท่า) เกมเลยตัดสินไวขึ้นมาก แต่มีกติกาซ่อน**ห้ามเดินตาที่เปิดช่องชนะ
พร้อมกันตั้งแต่ 2 ทางขึ้นไป** (เช่นวางสองเม็ดติดกันกลางแนวยาว 4 ช่องโดยทั้งสองปลายว่าง)
ทั้งสองฝ่ายเท่ากัน ยกเว้นตานั้นชนะเลยทันที — ถ้าไม่ห้าม ฝ่ายที่ได้ทำก่อนจะบังคับชนะได้
แทบทุกเกมภายใน ~4 ตา (คล้ายกติกาห้ามหมากสามซ้อนในโกะโมกุ/หมากห้า แต่ที่นั่นห้ามเฉพาะ
ฝ่ายเดินก่อน — เกมนี้ห้ามทั้งสองฝ่ายเท่ากัน เพราะผู้เล่นได้เป็นฝ่ายดำเสมอตอนเริ่มเกมกับคอม
ถ้าห้ามแค่ฝ่ายดำจะกลายเป็นคอมฝั่งขาวได้เปรียบทุกครั้งแทน)

ตัวเลือกกติกาในเมนู:

| ตัวเลือก | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| ขนาดกระดาน | 4×4 | 3×3 คลาสสิก หรือ 4×4 ตัดสินไว — เลือกได้จากเมนูก่อนเริ่มเกม |
| เดินได้เฉพาะช่องติดกัน | ปิด | เปิด = ย้ายได้เฉพาะช่องที่ติดกัน (รวมทแยง) |
| จับเวลาคิด 5 วินาทีต่อตา | ปิด | หมดเวลาเสียตานั้นให้อีกฝ่ายทันที (ไม่ใช่แพ้เกม) — มีวงแหวน
  นับถอยหลังในแถบตาที่กำลังเล่น เปลี่ยนเป็นสีแดงตอนเหลือไม่ถึง 1.5 วินาที ถ้าทั้งสองฝ่าย
  ปล่อยเวลาหมดติดกัน 3 รอบ (6 ตา) โดยไม่มีใครเดินเลย เกมจะจบเป็นเสมอกันเกมค้าง

## โหมดการเล่น

- **แข่งกับคอมพิวเตอร์** — 3 ระดับ (negamax + alpha-beta + iterative deepening)
- **แข่งกับเพื่อน** — ผลัดกันเล่นบนเครื่องเดียวกัน
- **เล่นออนไลน์** — สร้างห้องได้รหัส 5 ตัว ส่งให้เพื่อน เชื่อมตรงสองเครื่องผ่าน WebRTC (PeerJS)
  ไม่มีเซิร์ฟเวอร์เกมของเราเอง

## วิธีเล่น

ดับเบิลคลิก `index.html` ได้เลย ไม่ต้องติดตั้งอะไร

โหมดออนไลน์ต้องให้ทั้งสองฝ่ายเปิดหน้าเว็บเดียวกัน — เอาขึ้น GitHub Pages แล้วส่งลิงก์ให้เพื่อน
หรือส่งไฟล์นี้ให้เพื่อนไปเปิดเองก็ได้ (ต่ออินเทอร์เน็ตเพื่อโหลด PeerJS)

เปิดลิงก์ที่ลงท้ายด้วย `#รหัสห้อง` จะเด้งเข้าหน้าเข้าร่วมห้องให้อัตโนมัติ

## การควบคุม

| ทำอะไร | วิธี |
|---|---|
| หมุนกระดาน | ลากเมาส์ / ลากนิ้ว (เริ่มต้นเป็นมุมหน้าตรง ก้มลงเล็กน้อย) |
| ซูม | สกอร์ล |
| วาง/เดินหมาก | คลิกที่ช่อง |
| สลับมุมกล้องสำเร็จรูป | ปุ่ม ⌖ |

## เบื้องหลัง

ฉากทั้งหมดเป็น signed distance field ที่เดินรังสีทีละสเต็ปใน fragment shader ตัวเดียว

- **หมากโก๊ะ** = ส่วนร่วมของทรงกลมสองลูกที่เหลื่อมกัน (รูปเลนส์นูนสองด้าน) เชื่อมด้วย `smax`
  เพื่อลบสันคมตรงเส้นศูนย์สูตร
- **กระดาน** = rounded box + ลายเสี้ยนไม้ procedural + เส้นตารางฝังสีเข้ม — shader คอมไพล์
  ครั้งเดียวโดยจอง array (`uP`/`uPB`/`uCell`) ไว้สำหรับกระดานใหญ่สุด (4×4) เสมอ ส่วนขนาด
  กระดานที่เล่นจริง (3 หรือ 4) ส่งเข้าไปผ่าน `uniform float uBoardN` แทน สลับขนาดได้ทันที
  ไม่ต้องคอมไพล์ shader ใหม่ — ฝั่ง JS มีฟังก์ชัน `applyBoardSize(n)` สร้าง `LINES`/`ADJ`/
  `CELL_LINE_COUNT` ใหม่ทั้งหมดทุกครั้งที่สลับขนาด
- แสง: soft shadow แบบชดเชยระยะระหว่างสเต็ป, ambient occlusion, พื้นสะท้อนเงา, ACES tone mapping
- เสียงวางหมากสังเคราะห์สดด้วย WebAudio ไม่มีไฟล์เสียง
- **AI** ใช้ negamax + alpha-beta + iterative deepening น้ำหนักตำแหน่งอิงจาก "ช่องนี้เป็นส่วนหนึ่ง
  ของกี่เส้นชนะ" (ทั่วไปสำหรับกระดานขนาดไหนก็ได้ ไม่ฮาร์ดโค้ด "มุม/กลาง")
- **นาฬิกาจับเวลา** วงแหวน SVG นับถอยหลังฝังในแถบตา อัปเดตทุกเฟรมจาก `checkClock()` ที่เรียก
  จาก loop เรนเดอร์หลัก — enforce เฉพาะ "ตาของเครื่องนี้" (`myTurn()`) เท่านั้น โหมดออนไลน์
  แต่ละฝั่งคุมนาฬิกาตัวเองแล้วส่งข้อความ `skip` ข้ามเครือข่ายตอนหมดเวลา ไม่มีฝั่งไหนบังคับ
  ข้ามตาแทนอีกฝั่ง กันข้อมูลหลุดซิงก์

### บทเรียนที่แลกมาด้วยการดีบัก

- `calcNormal` ต้องใช้ epsilon **ใหญ่พอ** (0.018) ไม่งั้นผลต่างของ SDF จะจมไปกับความละเอียดของ
  `float` แล้วผิวหมากขึ้นริ้วเป็นวง ๆ เหมือนลายนิ้วมือ — เพิ่มความละเอียดการเดินรังสีไม่ช่วย
- soft shadow ที่ใช้ `min(k*h/t)` ตรง ๆ ทำให้เกิดริ้วเป็นแถบบนผิวโค้ง ต้องชดเชยระยะระหว่างสเต็ป
- ก้นกระดานห้ามอยู่ระนาบเดียวกับพื้นเป๊ะ ๆ ไม่งั้นการทดสอบเงารั่วเป็นแถบสว่างพาดใต้ขอบ
- **กระดานใหญ่ขึ้น = ต้องคิดเรื่องบังคับชนะใหม่** กระดาน 4×4 (24 เส้นชนะ) เปิดช่องให้ฝ่ายเดินก่อน
  สร้าง "คู่เปิดหัวท้าย" (double-open fork) ได้เสมอ ซึ่งเป็นการบังคับชนะ — ต้องเพิ่มกติกาห้ามเดินตา
  ที่เปิดช่องชนะพร้อมกัน 2 ทางขึ้นไปเพื่อแก้ (รอบแรกห้ามเฉพาะฝ่ายดำตามธรรมเนียมโกะโมกุ/หมากห้า
  แต่ผู้เล่นได้เป็นฝ่ายดำเสมอตอนเริ่มเกมกับคอม กติกาเลยบังคับใช้กับผู้เล่นฝ่ายเดียวจริง ๆ
  คอม/ฝ่ายขาวทำสิ่งที่ผู้เล่นทำไม่ได้ — ไม่แฟร์ ต้องแก้เป็นห้ามทั้งสองฝ่ายเท่ากัน)
- **ตัวกรองกติกาแพงห้ามอยู่ในลูปค้นหาลึกของ AI** ใส่ fork-filter ไว้ใน `legalMoves()` ตรง ๆ
  ทำให้ negamax เรียกมันซ้ำเป็นแสนครั้งตอนค้นลึกจนแท็บค้าง ต้องย้ายไปกรองแค่ที่ "จุดตัดสินใจจริง"
  (root ของ AI, ตาของผู้เล่นจริง, ไฮไลต์บนจอ) เท่านั้น
- **เช็คเวลาของ AI ตามความลึก (ply) ใช้ไม่ได้กับกิ่งก้านที่เยอะขึ้น** เดิมเช็คทุก 4 ชั้นความลึก
  ซึ่งพอกับกระดานเล็ก แต่กระดานที่กิ่งก้านต่อตาเยอะ (~48 ทาง) อาจสำรวจโหนดเป็นล้านก่อนถึงจุดเช็คแรก
  ต้องเปลี่ยนเป็นนับจำนวนโหนดที่สำรวจจริงแทน ไม่ว่ากิ่งก้านจะหน้าตายังไงก็เช็คถี่สม่ำเสมอ

## ทดสอบแล้ว

- 24 เส้นชนะของ 4×4 ไม่ซ้ำกัน ทุกเส้นต่อเนื่องจริง ทดสอบชนะทุกทิศทั้งแนวหลักและแนวซ้อนทับถูกต้อง
- AI ระดับยากและปานกลางชนะฝ่ายเดินสุ่มแทบทุกเกมทั้งสองขนาดกระดาน (ทั้งเดินก่อนและเดินหลัง)
- **4×4:** ยืนยันด้วยการจำลองว่าถ้าไม่ห้ามสร้างฟอร์ก จะบังคับชนะได้ทุกเกมภายใน ~4 ตา
  หลังเพิ่มกติกาห้ามฟอร์ก (ทั้งสองฝ่ายเท่ากัน) เกมยืดเป็น ~10 ตาขึ้นไป ไม่มีเกมไหนเสมอ
  และฝ่ายที่เก่งกว่า (ไม่ใช่แค่สีดำ) เป็นฝ่ายได้เปรียบ
- **3×3:** ยืนยันว่ากติกาห้ามฟอร์กของ 4×4 ไม่ถูกใช้ (กลยุทธ์คลาสสิกอย่างมุมตรงข้ามยังเล่นได้)
  และ AI ยากชนกันเองยังเสมอตามทฤษฎีคลาสสิกเดิม ไม่ได้เพี้ยนไปหลังรื้อโครงสร้างให้สลับขนาดได้
- สลับขนาดกระดานจากเมนูจริงหลายรอบ ตรวจว่าเส้นชนะ/ตำแหน่งเดินได้/กล้อง/บัฟเฟอร์เรนเดอร์
  สอดคล้องกันทุกครั้ง ไม่มีข้อมูลค้างจากขนาดก่อนหน้า
- เล่นจบเกมเต็มรูปแบบผ่าน `PointerEvent` จริง (ไม่เรียกฟังก์ชันตรง ๆ) พร้อมมือสั่นและกดค้างสุ่ม
  ทุกคลิก แล้วเทียบภาพที่เรนเดอร์จริงกับตรรกะเกมทุกตา — ตรงกันครบ ไม่มีคลิกไหนหลุด
- โหมดออนไลน์ทดสอบจับคู่จริงสองเครื่อง รวมถึงกรณีเจ้าของห้องเลือกกระดานคนละขนาดกับค่าเริ่มต้น
  ของผู้เข้าร่วม (ยืนยันว่าซิงก์ขนาดกระดานให้ตรงกันอัตโนมัติ) ซิงก์ครบทั้งช่วงวางและช่วงเดิน
  กันการเดินผิดตา และจับสัญญาณอีกฝ่ายหลุดได้
- **จับเวลา:** ยืนยันวงแหวน/ตัวเลขนับถอยหลังอัปเดตถูกต้อง, บังคับหมดเวลาแล้วเสียตาจริง
  โดยไม่แตะกระดาน, AI ไม่มีวันหมดเวลาเอง (งบคิดสูงสุด 1.4 วิ < 5 วิ) และวงแหวนซ่อนอัตโนมัติ
  ตอนไม่ใช่ตาของเครื่องนี้, ทดสอบข้ามเครือข่ายจริงว่าข้อความ `skip` ส่งครั้งเดียวไม่ซ้ำ
  (ยืนยันด้วยการจำลอง `skipTurn(true)` แบบไม่มีเวลาจริงคั่นกลาง — ได้ผลตาเปลี่ยนครั้งเดียว
  เป๊ะ ไม่มีตาหลุด) และยืนยัน safety net ที่จบเกมเป็นเสมอเมื่อทั้งสองฝ่ายปล่อยเวลาหมดติดกัน
  6 ตาทำงานถูกต้องจากการหมดเวลาจริงระหว่างทดสอบเอง
